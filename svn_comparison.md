# Сравнение Git и SVN

## 1. Почему в Git ветвление "дешёвое", а в SVN — "дорогое"?

В Git ветка — это просто указатель на коммит. Создание ветки занимает несколько миллисекунд и не требует копирования файлов. Вся история хранится локально, а ветки — это лишь ссылки на определённые коммиты.

В SVN ветка — это копирование директорий на сервере. Каждая новая ветка занимает место, требует времени на создание и является по сути отдельной папкой в репозитории. Это делает ветвление медленным и ресурсоёмким.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?

Нет, нельзя. SVN — централизованная система контроля версий. Коммит отправляется напрямую на центральный сервер, и без подключения к нему операция невозможна.

В Git коммит делается локально (в твоём репозитории), а синхронизация с удалённым сервером происходит отдельной командой `git push`. Поэтому в Git можно работать полностью офлайн.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?

SVN может быть предпочтительнее в следующих случаях:

- **Legacy-проекты.** Если проект уже много лет ведётся на SVN, переход на Git может быть дороже, чем поддержка существующей системы.
- **Жёсткий централизованный контроль.** В некоторых корпоративных и государственных структурах требуется единая точка хранения кода с полным контролем доступа — SVN это обеспечивает лучше.
- **Большие бинарные файлы.** Для проектов с большим количеством тяжёлых бинарных файлов (графика, видео) SVN иногда удобнее, чем Git, из-за особенностей работы с большими объектами.
- **Простота для новичков.** Модель SVN проще для понимания (один сервер, один репозиторий), чем распределённая модель Git.
